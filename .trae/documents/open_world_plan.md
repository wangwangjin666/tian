# 开放世界探索游戏 实施计划

## 环境调研结论

当前沙盒环境：
- **可用**：Node.js v24.1.0、Python 3.14.7、npm、git、浏览器渲染
- **不可用**：Unity 编辑器、Unreal/Godot 引擎、独立 GPU（`nvidia-smi` 无输出）
- **现有工作区**：仅有 `README.md` 和 `board_record.json`（与本任务无关）

基于以上约束，决定采用 **HTML5 Canvas + 原生 JavaScript** 构建一个 2D 程序化生成的开放世界探索游戏。该方案可在任何浏览器中直接运行，无需安装引擎，且能充分利用所有请求的插件/技能：

| 请求项 | 对应实现 |
|--------|---------|
| **algorithmic-art** | 程序化世界生成：Perlin/Simplex 噪声地形、生物群系、植被粒子系统 |
| **canvas-design** | 程序化生成瓦片/精灵资产、UI 元素（HUD、小地图） |
| **NVIDIA cuOpt 概念** | NPC 寻路系统：基于 A* 的优化路径规划（受 cuOpt 路由优化启发） |
| **Unity Workflows 理念** | 模块化架构、运行时验证、场景/实体分离、组件化设计 |
| **GitHub** | 创建仓库并推送代码 |

## 项目结构

```
/workspace/open-world/
├── index.html              # 游戏入口，Canvas 容器 + UI 叠加层
├── css/
│   └── style.css           # UI 样式（HUD、小地图、菜单）
├── js/
│   ├── main.js             # 游戏主循环、状态机
│   ├── noise.js            # Perlin/Simplex 噪声算法
│   ├── world.js            # 程序化世界生成（区块系统、生物群系）
│   ├── biomes.js           # 生物群系定义与配色
│   ├── player.js           # 玩家实体、移动、碰撞
│   ├── npc.js              # NPC 实体 + cuOpt 风格寻路
│   ├── pathfinding.js      # A* 寻路算法
│   ├── camera.js           # 相机跟随系统
│   ├── renderer.js         # Canvas 渲染管线
│   ├── input.js            # 键盘/鼠标输入处理
│   ├── minimap.js          # 小地图渲染
│   └── worldgen_philosophy.md  # 世界生成的算法哲学
└── README.md
```

## 实现步骤（依赖顺序）

### 步骤 1：创建项目骨架
- 建立目录结构、`index.html`、`css/style.css`
- 引入主循环框架（requestAnimationFrame）

### 步骤 2：噪声与世界生成（algorithmic-art 核心）
- 实现 `noise.js`：2D/3D Perlin 噪声，支持种子
- 实现 `world.js`：基于噪声的区块系统（chunk），无限世界
  - 高度图 → 地形（海洋/沙滩/草地/森林/山地/雪原）
  - 温度/湿度图 → 生物群系分类
  - 程序化放置树木、岩石、水体
- 编写 `worldgen_philosophy.md`：阐述生成算法的计算美学哲学

### 步骤 3：生物群系与配色（canvas-design）
- `biomes.js`：定义各生物群系的颜色、植被密度、可通行性
- 确保配色和谐，视觉层次清晰

### 步骤 4：玩家、相机与输入
- `input.js`：WASD/方向键移动
- `player.js`：玩家位置、速度、碰撞检测
- `camera.js`：平滑跟随相机，考虑区块加载

### 步骤 5：渲染管线
- `renderer.js`：分层渲染（地形层 → 植被层 → 实体层 → UI 层）
- 视锥体剔除，仅渲染可见区块
- 昼夜循环：天空色渐变、光照叠加

### 步骤 6：NPC 与寻路（NVIDIA cuOpt 启发）
- `pathfinding.js`：A* 算法，带网格权重（不同地形移动成本不同）
- `npc.js`：NPC 行为（漫游、寻路、避开障碍）
- 多种 NPC 类型（村民、动物）

### 步骤 7：UI 与小地图
- `minimap.js`：右下角小地图，显示玩家位置与周围地形
- HUD：坐标、生物群系名称、时间
- 简单菜单（ESC）

### 步骤 8：视觉资产生成（canvas-design）
- 用 Canvas API 程序化绘制瓦片纹理（草地、沙地、水面、雪地等）
- 程序化绘制简易精灵（玩家、树木、岩石、NPC）
- 确保像素风格统一

### 步骤 9：GitHub 集成
- `git init`、添加远程仓库
- 通过 GitHub MCP 创建远程仓库
- 提交并推送代码

### 步骤 10：验证
- 启动本地 HTTP 服务器
- 浏览器验证游戏可运行、移动流畅、世界无限生成、NPC 寻路正常

## 依赖与考虑

- **纯前端**：所有代码为原生 JS，无构建步骤，直接浏览器运行
- **性能**：区块缓存 + 视锥体剔除，确保大地图流畅
- **噪声种子**：固定种子保证可复现，同时支持随机种子探索
- **无外部资源**：所有瓦片/精灵均为程序化绘制，无外部图片依赖
- **浏览器兼容**：使用标准 Canvas 2D API，兼容现代浏览器

## 风险与应对

| 风险 | 应对 |
|------|------|
| 程序化生成性能不足 | 区块缓存、离屏 Canvas 预渲染、限制渲染半径 |
| 噪声地形视觉单调 | 多层噪声叠加（高度+温度+湿度），多生物群系 |
| A* 寻路开销大 | 限制寻路网格范围、路径缓存、NPC 数量上限 |
| GitHub 认证失败 | 先用 RequestAuthorization，失败则本地 git 即可 |
| 浏览器无法直接测试 | 启动本地 HTTP 服务器 + 浏览器自动化验证 |
